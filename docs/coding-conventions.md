# Coding conventions

I use four spaces for indentation, UpperCamelCase for classes and type aliases,
lowerCamelCase for functions and properties, and uppercase names for constants.
An expression body works well for a short result. Longer logic gets a block body.

Examples keep the names and sample data from my practice where they help explain
the syntax. Comments describe an operation or a result; a second full transcript
is usually unnecessary when the results are already beside the print calls.

[Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html).
